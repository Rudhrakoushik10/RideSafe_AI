1. PROJECT OVERVIEW
-------------------

RideSafe AI is a real-time two-wheeler helmet violation detection system that
uses deep learning to identify riders not wearing helmets from images and videos.

The system is designed to run on CPU-only machines (no GPU required), making it
suitable for deployment in traffic monitoring booths, police stations, and edge
computing devices.

Key Problem Solved:
- Manual monitoring of helmet compliance is impractical at scale
- Existing systems require expensive GPU hardware
- RideSafe AI provides automated detection with a simple web interface


2. TECH STACK AND JUSTIFICATION
---------------------------------

A. YOLOv8s (You Only Look Once - Version 8 Small)
   What: State-of-the-art object detection model by Ultralytics
   Why: Best speed/accuracy tradeoff for real-time detection. YOLOv8s (small)
     variant processes frames in ~50ms on CPU, fast enough for live analysis.
   How: Trained on 1,532 helmet images, outputs bounding boxes with class
     labels (With Helmet / Without Helmet)

B. ONNX Runtime
   What: Open Neural Network Exchange format for model deployment
   Why: Eliminates GPU dependency. The trained PyTorch model is exported to
     ONNX, which runs efficiently on CPU via ONNX Runtime. This means:
     * No CUDA/cuDNN installation needed
     * Works on any system with Python 3.8+
     * ~43MB model size, loads in under 1 second
   How: Model exported via ultralytics export, loaded via onnxruntime

C. Streamlit
   What: Python web framework for data science applications
   Why: Zero frontend code required. Built-in file upload, metrics display,
     charts, and progress bars. Perfect for rapid prototyping and demos.
   How: Single app.py file creates the entire UI with traffic signal theme

D. OpenCV
   What: Open-source computer vision library
   Why: Industry standard for image processing. Used for bounding box drawing,
     color space conversion (RGB/BGR), image resizing, and video frame capture.
   How: Processed frames are annotated with green (compliant) and red
     (violation) bounding boxes before display

E. NumPy
   What: Numerical computing library for Python
   Why: Efficient array operations for IoU computation, bounding box
     coordinate transformations, and fast matrix operations during detection.
   How: Used in tracker.py for IoU matrix computation between detections

F. IoU-based Multi-Object Tracker
   What: Intersection over Union based tracking algorithm
   Why: Lightweight alternative to deep learning trackers (DeepSORT, ByteTrack).
     No additional model weights needed. Sufficient for helmet detection where
     riders move predictably across frames.
   How: Computes IoU between consecutive frame detections, matches by
     Hungarian algorithm, assigns consistent track IDs

G. PyYAML
   What: YAML parser for Python
   Why: Configuration files in YAML format are human-readable and easy to
     modify. Thresholds, model paths, and rules can be changed without code.
   How: config/inference.yaml and config/violation_rules.yaml

H. Pandas
   What: Data manipulation library
   Why: Analytics dashboard needs tabular data display, chart generation,
     and historical scan tracking.
   How: Session scan history stored as DataFrame for Analytics tab

4. TRAINING DETAILS
--------------------

Dataset:
- Source: Roboflow (helmet detection dataset)
- Total images: 1,532
- Split: 1,069 train / 309 val / 154 test
- Classes: 2 (With Helmet, Without Helmet)
- Original 3-class labels (had 'licence' class) filtered to 2 classes

Training Configuration:
- Model: YOLOv8s (small variant, ~22M parameters)
- Epochs: 100
- Batch size: 16
- Image size: 640x640
- Optimizer: AdamW (default)
- Patience: 20 (early stopping)
- Augmentations:
  * Rotation: +/-10 degrees
  * Translation: 20%
  * Scale: 0.9
  * Shear: 5 degrees
  * Mixup: 0.2
  * Copy-paste: 0.3
  * Erasing: 0.4
  * Mosaic: 1.0
  * Horizontal flip: 0.5

Results:
- Overall mAP50: 0.823
- With Helmet: P=0.869, R=0.815, mAP50=0.894
- Without Helmet: P=0.810, R=0.656, mAP50=0.753
- Training time: ~2 hours on RTX 4060 (8GB VRAM)

Export:
- Format: ONNX Opset 13
- Size: ~43MB
- Inference: CPU (ONNX Runtime with CPUExecutionProvider)


5. KEY DESIGN DECISIONS
-------------------------

A. Why CPU-only inference?
   - Target deployment: traffic booths, police stations, edge devices
   - No GPU hardware dependency
   - Easier installation (no CUDA/cuDNN)
   - ONNX Runtime provides optimized CPU execution

B. Why in-memory storage (no database)?
   - Zero setup required (no MySQL/PostgreSQL installation)
   - Sufficient for single-session demos
   - Data persists during the session only
   - Reduces deployment complexity

C. Why YOLOv8s instead of YOLOv8n (nano)?
   - Nano model had poor accuracy for helmet detection (small objects)
   - Small variant provides 82.3% mAP50 vs ~60% for nano
   - Only 43MB vs 12MB for nano (acceptable tradeoff)
   - Still fast enough for real-time on CPU (~50ms/frame)

D. Why IoU-based tracker instead of DeepSORT?
   - No additional model weights needed
   - Lightweight (~0 extra memory)
   - Sufficient for short video clips
   - Easier to understand and maintain


6. DEMO INSTRUCTIONS (GPU-less Setup)
---------------------------------------

Steps for live demo:

1. Clone the repository:
   git clone https://github.com/Rudhrakoushik10/RideSafe_AI.git
   cd RideSafe_AI

2. Create virtual environment:
   python -m venv .venv
   .venv\Scripts\activate

3. Install dependencies:
   pip install -r requirements.txt

4. Run the application:
   streamlit run app.py

5. In the browser (http://localhost:8501):
   - Upload an image of two-wheeler riders
   - System auto-detects and shows results
   - Red boxes = No helmet (violation)
   - Green boxes = With helmet (compliant)
   - Click Analytics tab for session history

Sample images for demo:
- datasets/helmet/test/images/ (contains test images)

Expected output:
- Riders WITH helmet: Green bounding box, "HELMET OK" label
- Riders WITHOUT helmet: Red bounding box, "NO HELMET" label
- Fine amount displayed: Rs.1,000 per violation
- Compliance percentage calculated automatically


7. LIMITATIONS AND FUTURE WORK
--------------------------------

Current Limitations:
- Single session only (no persistent storage)
- No real-time camera feed integration
- Model accuracy: 82.3% mAP50 (some false negatives possible)
- Cannot detect helmets in extreme angles/occlusions

Future Enhancements:
- Add real-time CCTV camera integration
- Implement persistent database (SQLite/PostgreSQL)
- Add number plate recognition for automated challans
- Multi-class detection (helmet + wrong-side + red-light)
- Deploy on Raspberry Pi / Jetson Nano for edge computing
- Add WhatsApp/SMS notification for violations
- Mobile app for traffic police
